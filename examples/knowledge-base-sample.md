## L2 经历层（STAR 格式）

### 经历 1｜实习：后端开发实习生 @ 某科技公司（2025.07 - 2025.09）

- **一句话标题**：参与电商平台后端开发，独立负责订单模块
- **S 情境**：电商平台需要高并发订单处理能力
- **T 任务**：独立负责订单创建、支付回调、库存扣减等核心接口
- **A 行动**：
  - 基于 Spring Boot + MyBatis + MySQL 开发 RESTful 接口
  - 实现库存防超卖（数据库乐观锁 + 条件扣减），经 JMeter 并发验证
  - 设计统一返回体、全局异常处理、参数校验
  - 集成 Redis 缓存热点商品数据，QPS 提升 3 倍
  - 接入大模型 API 实现商品描述自动生成，封装重试 + 降级机制
- **R 结果**：订单模块稳定上线，日均处理订单 5000+，零线上事故
- **可追问细节**：
  - "库存防超卖为什么用数据库乐观锁？" → 保证并发下数据一致性，比分布式锁实现简单
  - "Redis 缓存击穿怎么处理？" → 热点数据永不过期 + 互斥锁重建

### 经历 2｜毕业设计：基于 RAG 的智能文档问答系统（负责人，2026.02 - 2026.05）

- **一句话标题**：自研 RAG 问答系统，实现文档自动向量化与精准检索
- **S 情境**：企业内部文档繁多，人工查找效率低
- **T 任务**：主导设计"文档解析 → 分段向量化 → 检索增强 → 问答生成"完整链路
- **A 行动**：
  - FastAPI 后端 + Vue3 前端，前后端分离架构
  - 使用 Chroma 向量数据库，支持余弦相似度检索
  - 实现混合检索（语义检索 + 关键词检索），召回率提升 25%
  - 设计提示词模板，约束模型只基于检索内容回答，降低幻觉率
  - Docker Compose 一键部署，支持文档批量上传
- **R 结果**：在 100 篇测试文档上，回答准确率 85%，平均响应时间 2.3 秒
- **可追问细节**：
  - "为什么用混合检索？" → 纯语义检索对专有名词不敏感，混合检索兼顾语义和关键词
  - "怎么降低幻觉？" → 提示词约束 + 检索结果引用 + 不知道就明确说不知道

### 经历 3｜项目：校园二手交易微服务平台（主要负责人，2025.03 - 2025.06）

- **一句话标题**：基于 Spring Cloud Alibaba 的分布式微服务电商平台
- **S 情境**：校园二手交易需要多服务独立部署、弹性扩展
- **T 任务**：负责商品微服务和用户微服务，搭建分布式基础设施
- **A 行动**：
  - Nacos 服务注册发现 + 配置中心，Gateway 网关路由
  - Sentinel 限流熔断，保护核心接口
  - Seata 分布式事务，保证订单与库存一致性
  - MySQL 读写分离，Elasticsearch 商品搜索
- **R 结果**：支持 500+ 并发用户，商品搜索响应 < 200ms
- **可追问细节**：
  - "分布式事务怎么保证一致性？" → Seata AT 模式，一阶段提交 + 二阶段回滚
  - "Sentinel 限流规则怎么配置？" → 基于 QPS 阈值 + 慢调用比例熔断

### 经历 4｜校园：学生会技术部 部长（2023.09 - 2025.06）

- **一句话标题**：统筹学生会技术支持，主导校园活动系统开发
- **S 情境**：学生会活动需要线上报名、签到、投票等功能
- **T 任务**：带领 5 人团队开发校园活动管理系统
- **A 行动**：
  - 需求分析 + 任务拆分 + 代码审查，协调前后端进度
  - 开发报名、签到、抽奖等模块，支持 2000+ 人同时在线
  - 组织技术分享，提升团队整体水平
- **R 结果**：系统稳定运行 2 年，服务 30+ 场校园活动
- **可追问细节**："带团队遇到最大的困难？" → 成员技术水平参差不齐，通过结对编程 + 代码审查提升质量

## L6 面试常见问题与答案（软素质 + 高频追问）

> 本层答案基于 L1-L5 虚构经历编写，用于演示"软素质问题如何被知识库兜住"。
> 切分建议：**每条 Q+A 独立成条**，保证软素质问题精准召回。

### ① 抗压能力

**Q：你抗压能力怎么样？**
A：有真实的多线作战经历：大四实习（7-9月）和毕设（2-5月）收尾期重叠，白天写订单模块，晚上调 RAG 检索效果，最后两边都交付了——订单模块日均 5000+ 单零线上事故，毕设回答准确率 85%。我的办法是列清单拆任务、按优先级做，不让自己陷入"什么都做不完"的状态。

### ② 团队协作

**Q：你怎么看待团队协作？**
A：三个真实场景：数学建模省二三人分工（建模/编程/写论文），体会到"把接口定清楚各干各的也很快"；毕设我是负责人，自己拆需求排进度；学生会带 5 人团队做活动系统，需求拆解、代码审查、进度协调都是我在做。协作对我来说是把目标拆开、各管一段、再合起来。

### ③ 缺点

**Q：你最大的缺点是什么？**
A：前端视觉细节不擅长（CSS 精细调优做不来），C++/Go/Rust 没实际用过，大数据生态（Hadoop/Spark/Flink）和 K8s 只接触没深入。被问到我会直接说"这个我不太确定"，我的原则是不装懂，先说明掌握程度再谈思路。

### ④ 职业规划

**Q：你的职业规划是什么？**
A：短期 1-3 年把 Java 后端工程能力做扎实（实习和微服务项目已跑通 Spring 全家桶，想接触真实生产的高并发场景）；中期结合 RAG 和大模型应用的落地经验，往"业务 + AI 工程化"方向走。不追求频繁跳槽，想找一个能长期深耕的团队。

### ⑤ 为什么选我们公司

**Q：为什么选择我们公司？**（模板口径，面试前按公司填充）
A：我对贵公司的了解是（此处填业务方向/技术栈），这和我简历里的 Java 后端 + RAG 落地经验匹配；我是应届生但有真实的微服务和 AI 应用经验，能直接上手。也想借此了解团队后端技术栈演进方向和新人培养路径。

### ⑥ 最大困难

**Q：你遇到过的最大困难是什么？**
A：毕设的 RAG 检索效果调优。初期纯语义检索对专有名词不敏感，答案经常偏。我没盲目试，先定位问题——加 BM25 混合检索，召回率提升 25%，再配合提示词约束降低幻觉，最终准确率 85%。这让我养成"先定位、再动手"的习惯。

### ⑦ 加班看法

**Q：你怎么看待加班？**（参考口径）
A：应届阶段我愿意投入，实习上线前就是加班盯并发验证过来的。但我更看重效率——需求拆清楚、测试前置，很多加班可以避免。我的态度是"任务需要我可以顶，但希望团队也讲方法"。

### ⑧ 期望薪资

**Q：你期望薪资多少？**
A：这个咱们面试时可以当面聊。（统一口径，可反问"方便先了解下贵司这个岗位的薪资结构吗"）

### ⑨ 面试结尾反问

**Q：你有什么想问我们的？**

### ⑩ 最大优势

**Q：你最大的优势是什么？和别的应届生有什么不同？**
A：我是"能写代码 + 懂 AI 落地 + 带过团队"的应届生。实习真接了大模型 API（重试+降级工程兜底）、真做了 Redis 缓存优化（QPS 提升 3 倍）、毕设完整实现了 RAG 全链路（解析→向量化→混合检索→生成）。不是"了解 AI"，是"用 AI 解决过真实问题"。

### ⑪ 为什么应聘软件开发岗

**Q：你为什么应聘软件开发岗位？**
A：主修计算机科学与技术，Java 后端从实习到微服务项目一路在做，能直接上手；同时有完整的大模型应用落地链路（接入→调优→部署→测试），软件开发需要这种"能落地"的工程思维。另外党员、学生干部出身，稳定性强，愿意长期深耕。

### ⑫ 实习最大收获

### ⑬ 对大模型 / AI 应用的看法

**Q：你怎么看大模型 / AI 应用？**
A：我的观点是"大模型是能力，不是产品"，落到业务里才有价值。毕设的 RAG 问答、实习的商品描述生成，本质都是把 AI 变可用。我自己也用 Dify + DeepSeek 搭过个人知识库问答 Agent，对 RAG 全链路有实操认知。

### ⑭ 最近在学什么
